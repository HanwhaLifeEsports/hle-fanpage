# 자동화 로드맵

지금은 전부 수동입니다 — 게임 찾고, 관전 띄우고, OBS 켜고, 유튜브 시작하고, 끝나면 반복.
이걸 어디까지 자동으로 만들 수 있고, **어디부터는 만들면 안 되는지** 정리합니다.

먼저 결론: **완전 무인은 권하지 않습니다.** 아래 4단계 중 3단계까지가 현실적인 목표입니다.

---

## 현재 상태

```
[사람] 게임 찾기 → [사람] 관전 실행 → [사람] UI 끄기 → [사람] OBS 송출 → [사람] 종료 확인 → 반복
         spectate.mjs 가 앞의 둘만 대신함
```

---

## 1단계 — 감시 데몬 (반나절)

**목표**: 선수가 게임을 시작하면 알아서 관전 창을 띄운다. 송출은 사람이 시작.

새 파일 `overlay/watch.mjs`:

```
상태 머신
  IDLE ──(선수 게임 감지)──▶ WAITING ──(gameLength ≥ 200초)──▶ LAUNCHING
    ▲                                                              │
    │                                                              ▼
    └──────(게임 종료 / 재시도 소진)────── SPECTATING ◀──(스트림 수신 확인)
```

- `config.js` 의 `TRACKED` 를 puuid 로 한 번 해석해 캐시 (라이엇 ID → puuid 는 안 바뀝니다)
- 60초마다 5명의 `active-games` 확인
- 감지하면 관전 지연(약 3분)을 기다렸다가 `spectate.mjs` 의 실행·검증 로직 재사용
- 스트림이 붙으면 상태 파일(`/tmp/soloq-state.json`)에 기록 — 오버레이와 OBS 가 이걸 봅니다

### 폴링 예산 (개발용 키 100회/2분 기준)

| 용도 | 주기 | 2분당 호출 |
|---|---|---|
| 선수 5명 감지 | 60초 | **10회** |
| 관전 중 종료 확인 | 60초 | 2회 |
| 여유 | | 88회 |

한도의 12% 입니다. 넉넉합니다. **다만 Development 키는 24시간마다 만료**되므로,
상시로 돌릴 거면 Personal 키를 받아두세요. 401 이 뜨면 데몬은 멈추고 알림만 남겨야 합니다
(자동 재발급은 불가능합니다 — 웹 로그인이 필요합니다).

---

## 2단계 — OBS 연동 (하루)

**목표**: 관전이 붙으면 OBS 가 알아서 송출을 시작하고, 끝나면 멈춘다.

OBS 는 **obs-websocket** 이 내장돼 있습니다 (도구 → WebSocket 서버 설정).
비밀번호를 켜고 `.env.local` 에 넣은 뒤, `watch.mjs` 가 이렇게 씁니다:

| 시점 | 호출 |
|---|---|
| 스트림 수신 확인 | `StartStream` |
| 게임 종료 감지 | `StopStream` |
| 관전 대기 중 | 대기 화면 씬으로 `SetCurrentProgramScene` |

> **송출 시작 전에 최소 10초는 두세요.** 관전 창이 뜨자마자 송출하면 로딩 화면이 그대로 나갑니다.
> 오버레이가 `body.live` 를 붙이는 시점을 신호로 쓰면 정확합니다.

유튜브 방송은 **상시 방송(persistent broadcast)** 으로 하나 만들어 두고 붙였다 떼는 쪽을 권합니다.
매번 새 방송을 만들면 YouTube Data API 할당량(하루 10,000 유닛, 방송 생성이 50 유닛)과
채널 알림 스팸이 문제가 됩니다.

---

## 3단계 — 무인 운전 + 안전장치 (하루)

여기까지가 **권장 종착점**입니다.

| 안전장치 | 이유 |
|---|---|
| 하루 최대 방송 시간 상한 (예: 4시간) | 새벽에 무한 방송이 도는 것을 막습니다 |
| 연속 실패 3회 → 30분 정지 | op.gg 프록시 장애 시 재시도 폭주 방지 |
| 시간대 창 (예: 18:00–02:00) | 선수가 잘 시간에 켜지지 않게 |
| 키 만료(401) → 즉시 정지 + 알림 | 조용히 계속 실패하는 것보다 낫습니다 |
| 맥 절전 방지 (`caffeinate -dimsu`) | 화면이 잠들면 OBS 캡처가 검게 나갑니다 |
| 로그 파일 (무엇을 왜 했는지) | 사후에 원인을 찾을 수 있어야 합니다 |

launchd 로 로그인 시 자동 시작하게 하려면 `~/Library/LaunchAgents/` 에 plist 를 두면 됩니다.
`KeepAlive` 는 **끄세요** — 죽었을 때 자동 재시작이 오히려 폭주를 만듭니다.

---

## 4단계 — 완전 무인 · 권장하지 않음

기술적으로는 가능합니다. 그런데 하지 마세요. 이유는 아래.

---

## 자동화하면 안 되는 것

### 1. 방송 시작 판단 — 사람이 봐야 합니다

선수 솔랭 방송은 **선수 본인이 원치 않을 수 있습니다.** 무인으로 24시간 돌면
"내가 자는 사이에 내 게임이 방송되고 있었다" 가 됩니다. 트롤링·욕설·부계정 등
방송에 나가면 곤란한 상황도 사람이 판단해야 합니다.

최소한 **"오늘 방송 켠다" 는 사람이 누르는 것**으로 남겨두세요. 그 뒤의 게임 전환은 자동이어도 됩니다.

### 2. 계정 식별 — 절대 추측 금지

`TRACKED` 에 확인 안 된 계정을 넣으면 **엉뚱한 일반인의 플레이가 "HLE 선수" 로 방송됩니다.**
자동 탐색(이름 유사도 등)은 만들지 마세요.

### 3. 방송 제목·설명 자동 생성

"Zeka 랭크 게임" 같은 제목이 자동으로 붙으면, 그 게임이 부계정이거나 다른 사람이면
사실과 다른 정보가 채널에 남습니다. 템플릿을 고정하고 선수명은 넣지 않는 편이 안전합니다.

---

## 솔직한 리스크

**op.gg 프록시 의존이 가장 약한 고리입니다.**
라이엇의 `spectator.kr.lol.pvp.net` 은 이 PC 에서 4/4 실패했고(메타데이터 무한 정지),
실제로 동작한 것은 `kr.spectator.proxy.op.gg` 뿐입니다. 그런데 그것도 **5번 중 2번만** 붙었습니다.
op.gg 가 이 프록시를 닫거나 차단하면 **전체가 멈춥니다.** 대체 경로는 지금 없습니다.
자동화를 만들더라도 이 실패를 "정상 상태" 로 다루도록 설계하세요.

**약관·사회적 리스크.**
관전 자체는 라이엇이 공개한 기능이고 관전 방송은 흔합니다. 다만 특정 선수를 지목해
상시 추적·송출하는 것은 팬 문화의 선을 넘을 수 있습니다. 선수·구단·라이엇의 요청이 오면
즉시 내릴 수 있어야 하고, 팬페이지 `/soloq` 에 이미 그 문구를 넣어뒀습니다.

**관전의 3분 지연은 유지하세요.** 지연을 줄이려는 시도는 스트림 스나이핑 도구가 됩니다.
